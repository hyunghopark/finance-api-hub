# 금융감독원 DART 서버 (dart)

`dart/server/index.js`는 금융감독원 전자공시(DART) 오픈 API를 조회 전용으로 제공한다. 호출 대상은 `opendart.fss.or.kr` 하나이고, 인증키는 환경변수 `DART_API_KEY`나 macOS 키체인에서 읽는다. 도구는 8개다.

## 회사 지정을 고유번호로 바꾸기

DART API는 회사를 8자리 고유번호(`corp_code`)로만 받는다. 종목코드나 회사명으로는 조회할 수 없다. 그래서 거의 모든 도구가 먼저 `resolveCorp()`로 입력을 고유번호로 바꾼다.

입력 형태에 따라 처리가 갈린다.

| 입력 | 처리 |
|---|---|
| 숫자 8자리 | 고유번호로 보고 그대로 사용 (목록을 읽지 않음) |
| 영숫자 6자리 | 종목코드로 보고 목록에서 찾음. 숫자 6자리인데 없으면 오류 |
| 그 밖 | 회사명이 **정확히 일치**하는 것을 찾음 |

회사명은 부분 일치로 자동 선택하지 않는다. 이름이 같은 회사가 여럿이면 상장사가 하나일 때만 그것을 고르고, 그래도 정해지지 않으면 후보 최대 10개(상장사 우선)를 오류 문구에 담아 돌려준다. 잘못된 회사의 재무제표를 조용히 돌려주는 것보다 에이전트가 후보를 보고 다시 지정하게 하는 편이 안전하기 때문이다. 이름 일부로 찾으려면 `dart_find_corp`를 쓴다.

### 고유번호 목록

목록은 DART가 zip으로 묶은 XML 한 파일로 제공한다. `loadCorpList()`가 이를 받아 풀고 `~/.dart-mcp/corpcode.json`에 저장하며, 7일이 지나면 다시 받는다. 신규 상장사는 그만큼 늦게 잡힐 수 있어 `dart_find_corp`의 `refresh` 인자로 즉시 다시 받을 수 있다. 캐시 수명은 [호출 한도와 캐시](../architecture/rate-limits-and-caching.md)에 정리돼 있다.

## 외부 패키지 없이 zip 풀기

고유번호 목록과 공시 원문은 zip으로 온다. 저장소 원칙상 외부 패키지를 쓰지 않으므로 `unzip()`이 zip 형식을 직접 읽는다. 파일 끝에서 중앙 디렉터리 끝 레코드를 찾고, 항목마다 압축 방식이 무압축이면 그대로, deflate면 내장 `zlib`으로 푼다. 그 밖의 방식은 데이터가 `null`로 남는다.

zip이어야 할 응답이 zip이 아닐 수 있다. 키가 틀리거나 문서가 없으면 DART는 오류를 XML이나 JSON으로 보낸다. `assertZip()`이 첫 4바이트로 zip인지 확인하고, 아니면 본문에서 상태 코드와 메시지를 뽑아 오류로 만든다.

한글 인코딩도 직접 처리한다. `decodeText()`는 문서 앞부분의 `encoding` 선언을 먼저 따르고, 없으면 UTF-8, EUC-KR 순으로 시도한다. 오래된 공시 원문이 EUC-KR이기 때문이다.

## DART 상태 코드

DART는 HTTP 200으로 응답하면서 본문의 `status`로 결과를 알린다. `dartJson()`이 이를 해석한다.

- `000`은 정상이다.
- `013`(조회된 데이터 없음)은 **오류가 아니라 빈 목록**으로 바꿔 돌려준다. 해당 연도에 배당이 없거나 공시가 없는 것은 정상적인 결과이기 때문이다. 도구들은 빈 결과일 때 대신 무엇을 조회할지 `note`로 안내한다.
- 그 밖의 코드는 한국어 설명을 붙인 오류가 된다(`020`은 하루 2만 건 한도 초과).

`013`을 빈 결과로 두지 않는 도구가 하나 있다. 기업 개황(`dart_company`)에서는 `013`이 "그 고유번호의 회사가 없다"는 뜻이다. 8자리 숫자는 목록 확인 없이 고유번호로 통과하므로, 없는 번호를 주면 이전에는 내용 없는 결과가 정상 응답으로 돌아왔다. 지금은 `companyResult()`가 이를 "고유번호를 DART에서 찾지 못함" 오류로 바꾸고 `dart_find_corp`로 확인하라고 안내한다. 회사가 있으면 `status`와 `message`만 뺀 응답을 그대로 돌려준다.

## 도구 구성

| 도구 | 내용 |
|---|---|
| `dart_find_corp` | 회사명 일부나 종목코드로 고유번호 찾기 |
| `dart_company` | 기업 개황 |
| `dart_disclosures` | 공시 목록 검색 |
| `dart_financials` | 재무제표 (주요계정 또는 전체) |
| `dart_indicators` | DART가 계산한 재무지표 (수익성·안정성·성장성·활동성) |
| `dart_dividends` | 배당에 관한 사항 |
| `dart_report` | 정기보고서 주요정보·지분공시·주요사항보고서 |
| `dart_document` | 공시 원문 텍스트 |

### 단일 회사와 여러 회사

`dart_financials`와 `dart_indicators`는 `corp`에 쉼표로 여러 회사를 넣을 수 있다. 회사 수에 따라 DART의 다른 API를 고른다. 재무제표는 한 회사면 단일회사 API, 여러 회사면 다중회사 주요계정 API를 부르고, 여러 회사는 주요계정(`scope=major`)만 허용한다. 응답에 빠진 회사는 `missing`으로 알려 준다.

8자리 고유번호로 준 회사는 목록을 읽지 않고 통과하므로 이름과 종목코드가 비어 있다. 한 회사일 때는 문제가 없지만, 여러 회사 결과에서는 행마다 어느 회사인지 구분할 이름이 필요하다. 그래서 `resolveCorps()`는 회사가 둘 이상이고 이름 없는 항목이 있으면 고유번호 목록에서 이름과 종목코드를 채운다. 목록을 받지 못하면 이름 없이 그대로 조회한다. 행에 회사명을 붙이는 `nameOf()`도 이름이 있는 항목만 인정해, 끝까지 찾지 못했을 때만 고유번호를 대신 보여 준다.

전체 재무제표(`scope=all`)는 연결(CFS)을 먼저 조회하고, 결과가 없고 사용자가 연결·별도를 지정하지 않았으면 별도(OFS)로 한 번 더 조회한다. 연결 재무제표를 내지 않는 회사가 있기 때문이다.

### dart_report: 도구 하나로 여러 API

`dart_report`는 `endpoint` 인자로 DART API 50여 개를 고르는 도구다. 허용 목록은 세 묶음이고, 묶음에 따라 필요한 인자가 다르다.

| 묶음 | 예 | 필요한 인자 |
|---|---|---|
| 정기보고서 주요정보 | 최대주주 현황, 임원 현황, 자기주식 | `year`, `report` |
| 지분공시 | 대량보유 상황보고, 임원·주요주주 소유보고 | `corp`만 (`bgn_de`, `end_de`는 선택) |
| 주요사항보고서 | 유상증자·합병·자기주식 취득 결정, 부도·회생 | `bgn_de`, `end_de` |

`KIND()`가 엔드포인트가 어느 묶음인지 판정해 인자 검증을 나눈다. 목록에 없는 이름은 요청을 보내기 전에 거부한다. 도구 설명에는 전체 엔드포인트 이름과 한국어 제목이 나열되어 에이전트가 고를 수 있다.

#### 나눠 받기

결과는 `pageReport()`를 거쳐 쪽 단위로 나간다. `limit`(기본 100, 최대 500)과 `offset`(기본 0)으로 범위를 정한다. 응답에는 전체 행 수(`count`와 `total`, 같은 값), 이번에 준 행 수(`shown`), `offset`이 들어가고, 뒤에 더 남았으면 `next_offset`이 붙는다. 이 값을 다음 호출의 `offset`에 넣어 이어 받는다.

지분공시 묶음은 따로 처리한다. DART는 지분공시를 기간 인자 없이 전체를 오래된 순으로 준다. 임원·주요주주 소유보고처럼 행이 많은 회사에서는 앞쪽의 오래된 자료만 보이게 되므로, 서버가 접수일(`rcept_dt`) 최신순으로 다시 정렬한다. 접수일이 같으면 접수번호가 큰 것이 앞이다. `bgn_de`·`end_de`를 주면 DART에 보내지 않고 받은 행을 접수일로 거른다. 이 두 인자는 8자리 숫자인지 요청 전에 확인한다.

정기보고서 주요정보와 주요사항보고서는 DART가 준 순서를 그대로 둔다.

### dart_document: 원문 읽기

공시 원문을 zip으로 받아 풀고 태그를 지운 텍스트로 돌려준다. `htmlToText()`는 문단·행 끝을 줄바꿈으로, 표의 칸 끝을 ` | `로 바꿔 표 구조가 텍스트에서도 읽히게 한다.

원문이 길 수 있어 두 가지 읽기 방식을 둔다.

- `offset`과 `max_chars`로 나눠 읽는다. 응답의 `next_offset`이 다음 위치다.
- `find`에 단어를 주면 그 단어가 나오는 곳의 앞뒤 400자만 최대 15곳 돌려준다.

한 공시에 파일이 여러 개면 `files` 목록과 `file_index`로 고른다.

## 출력 한도

도구 응답은 6만 자를 넘지 않으며 항상 유효한 JSON이다. 넘으면 `fitOutput()`이 앞쪽 행을 남기고 행 수를 줄인 뒤 `truncated: true`, 실제 행 수 `shown`, 안내 `note`를 붙인다. 공통 동작은 [MCP 서버 공통 구조](../architecture/server-anatomy.md)의 "출력 한도"에 있다.

dart에서는 도구 객체가 줄이는 방법을 직접 갖고 있다.

- `rowsKey`: 줄일 배열의 이름. 도구마다 `results`, `list`, `rows`로 다르다. 없으면 가장 큰 배열을 줄인다.
- `narrow`: `note` 끝에 붙는, 그 도구에서 범위를 좁히는 방법. 예를 들어 `dart_financials`는 전체 재무제표를 `statement`로 하나씩 받으라고 안내한다.
- `afterFit`: 줄인 뒤 결과를 고치는 함수. `dart_report`만 쓴다. 행이 줄어든 만큼 `next_offset`을 앞당겨, 그대로 이어 받아도 빠지는 행이 없게 한다.

도구가 이미 `note`를 넣은 결과라면 그 문구를 지우지 않고 뒤에 ` / `로 이어 붙인다.

## 공시 목록의 기본값

`dart_disclosures`는 기간을 비우면 종료일을 한국 시각 오늘로, 시작일을 30일 전으로 잡는다. 정정 전 원보고서는 기본으로 제외한다. `title_contains`는 DART에 보내는 조건이 아니라 받은 페이지 안에서 보고서명을 거르는 것이므로, 결과가 여러 페이지면 페이지마다 따로 적용된다.

각 결과에는 DART 원문 보기 주소가 함께 들어간다.
