# SEC EDGAR 서버 (edgar)

`edgar/server/index.js`는 미국 증권거래위원회(SEC)의 EDGAR 자료를 조회 전용으로 제공한다. 도구는 7개이고, 다른 서버와 달리 도구 이름이 폴더 이름이 아니라 `sec_`로 시작한다(`sec_filings`, `sec_financials` 등).

## 키가 없는 서버

SEC는 API 키를 발급하지 않는다. 대신 요청마다 연락처가 든 User-Agent를 요구하고, 없으면 403을 돌려준다. 서버는 환경변수 `SEC_USER_AGENT`나 macOS 키체인에서 이 문자열을 읽으며, 이메일 주소(`@`)가 없으면 받지 않는다.

User-Agent에는 사용자의 이름과 이메일이 들어 있어 비밀 값처럼 다룬다. 오류 문구에서 User-Agent 전체와 이메일 형태의 문자열을 모두 가린다([인증 정보와 비밀 값 처리](../architecture/credentials-and-secrets.md)).

## 호스트 세 곳

SEC 자료는 호스트가 나뉘어 있다.

| 호스트 | 내용 |
|---|---|
| `data.sec.gov` | 회사별 공시 이력, XBRL 사실 값 |
| `www.sec.gov` | 공시 원문, 티커 목록 |
| `efts.sec.gov` | 공시 전문 검색 |

`secGet()`은 이 세 곳이 아닌 주소를 거부한다. 리디렉션 응답도 https이고 이 집합 안의 호스트일 때만, 최대 3번까지 따라간다. 원문을 읽는 도구는 사용자가 준 주소를 받으므로 더 좁게 검사한다. `validArchiveUrl()`이 `www.sec.gov`의 `/Archives/edgar/data/` 아래이고 `..`이 없는 주소만 허용한다.

전문 검색이 쓰는 `efts` 엔드포인트는 SEC 공식 API 문서에 올라 있지 않다. 형식이 바뀔 수 있다는 점이 도구 설명에 적혀 있다.

요청 속도 조절, 재시도, 응답 캐시는 [호출 한도와 캐시](../architecture/rate-limits-and-caching.md)에 정리돼 있다.

## 회사 지정을 CIK로 바꾸기

SEC는 회사를 10자리 번호(CIK)로 식별한다. `resolveCompany()`가 입력을 CIK로 바꾼다.

1. 숫자만 있으면 CIK로 보고 10자리로 채운다. 목록을 읽지 않는다.
2. 티커와 정확히 일치하면 그 회사다. 입력의 `.`은 `-`로 바꿔 비교한다(`BRK.B` → `BRK-B`).
3. 아니면 공백으로 나눈 모든 단어가 회사명에 들어 있는 회사를 찾는다. 결과가 한 회사면 그것을 쓴다.
4. 여럿이면 이름이 정확히 같은 회사가 하나일 때만 고르고, 아니면 후보 최대 8개를 담은 오류를 낸다.

티커 목록에는 현재 상장된 회사만 있다. 상장폐지되거나 비상장인 회사는 찾지 못하므로 CIK 숫자로 지정해야 하고, 오류 문구가 이를 안내한다.

같은 회사가 티커를 여러 개 가질 수 있어(보통주와 우선주 등) 후보를 CIK 기준으로 중복 제거한 뒤 개수를 센다.

## XBRL 사실 값을 시계열로 정리하기

`sec_financials`는 매출, 순이익, 자산 같은 핵심 항목을 연간이나 분기 시계열로 돌려준다. SEC가 주는 XBRL 사실 값은 그대로 쓰기 어려워 `buildSeries()`가 세 가지를 처리한다.

### 같은 기간의 중복 제거

XBRL 사실 값의 회계연도 표시는 "그 값이 실린 공시" 기준이다. 올해 10-K에는 작년, 재작년 값도 비교용으로 다시 실리고, 정정 공시가 있으면 같은 기간의 값이 여러 번 나온다. `dedupe()`는 기간의 시작일과 종료일로 값을 묶어 **가장 늦게 공시된 값** 하나만 남긴다. 정정된 수치가 있으면 정정 후 값이 쓰인다.

### 기간 길이로 연간과 분기 구분

기간이 있는 항목(매출, 이익, 현금흐름)은 시작일과 종료일의 차이로 종류를 판정한다.

| 종류 | 일수 |
|---|---|
| 연간 | 340~380일 |
| 분기 | 80~100일 |
| 6개월 누적 | 165~200일 |
| 9개월 누적 | 250~290일 |

시점 값(자산, 부채, 자본)은 기간이 없다. 연간 모드에서는 연간 보고서(10-K, 20-F, 40-F)의 회계연도 말 값만 고른다.

### 4분기 계산

미국 회사는 4분기 실적을 따로 공시하지 않는다. 10-K에는 연간 값만 있다. 분기 모드에서 서버는 4분기를 **연간 값 − 9개월 누적 값**으로 계산한다. 시작일이 같은 연간 값과 9개월 누적 값을 짝지어 빼고, 결과 행에 `derived: true`를 붙여 계산값임을 표시한다. 연간 종료일 3일 이내에 끝나는 분기 값이 이미 있으면 계산하지 않는다.

### 누적값만 공시되는 항목의 2·3분기

현금흐름표 항목(영업현금흐름, 설비투자)은 10-Q에 분기 값이 아니라 연초부터의 누적값만 실린다. 1분기 보고서의 3개월 값, 2분기 보고서의 6개월 누적, 3분기 보고서의 9개월 누적이 전부다. 분기 길이의 값만 고르면 1분기만 남는다.

그래서 분기 모드는 4분기와 같은 방식으로 2·3분기도 만든다.

| 분기 | 식 | 짝짓는 기준 |
|---|---|---|
| 2분기 | 6개월 누적 − 1분기 | 시작일이 같은 분기 값 |
| 3분기 | 9개월 누적 − 6개월 누적 | 시작일이 같은 6개월 누적 |
| 4분기 | 연간 − 9개월 누적 | 시작일이 같은 9개월 누적 |

계산한 행의 기간은 앞 누적의 종료일 다음 날부터 뒤 누적의 종료일까지이고, 공시 정보는 뒤 누적의 것을 쓰며 `derived: true`가 붙는다. 누적 종료일 3일 이내에 끝나는 분기 값이 직접 공시돼 있으면 계산하지 않는다. 매출처럼 분기 값이 그대로 공시되는 항목에는 계산값이 섞이지 않는다.

뺄셈은 `subtractExact()`를 거친다. 부동소수 연산은 `8.98 − 6.88`을 `2.1000000000000005`로 내놓는다. 주당순이익처럼 소수인 항목에서 계산한 분기 값에 이런 꼬리가 붙지 않도록, 결과를 두 피연산자 중 소수 자릿수가 많은 쪽에 맞춰 반올림한다. 정수끼리의 뺄셈은 그대로 두고, 직접 공시된 값은 건드리지 않는다.

짝이 될 값이 없으면 그 분기는 만들 수 없다. `buildSeries()`는 이런 분기를 조용히 건너뛰지 않고 따로 모아 돌려주고, `sec_financials`가 항목의 `note`에 "빠진 분기: (종료일)에 끝나는 N분기"와 없는 값을 적는다. 알리는 것은 표시 범위 안에 있고 다른 태그 후보로도 채워지지 않은 분기뿐이다.

### 항목 이름의 후보

같은 개념도 회사와 시기에 따라 XBRL 태그가 다르다. `METRICS`는 항목마다 태그 후보를 순서대로 둔다. 예를 들어 매출은 네 가지 태그를, 순이익은 두 가지를 차례로 시도한다. 회사가 해당 태그를 쓰지 않으면 SEC가 404를 주는데, `getConcept()`이 이를 오류가 아닌 "없음"으로 바꿔 다음 후보로 넘어가게 한다.

목록에 없는 항목은 `sec_concept`로 태그 이름을 직접 지정해 조회한다. 태그와 분류 체계 이름은 주소 경로에 들어가므로 정규식으로 형식을 확인한다.

`sec_concept`는 **양식(`forms`)과 시작일(`from`)로 먼저 거른 뒤** 기간별로 가장 늦게 공시된 값을 고른다. 순서가 반대면 문제가 생긴다. 같은 연간 값이 10-K 뒤에 다른 양식(주주총회 위임장 DEF 14A, 다음 분기 10-Q)에 다시 실린 회사에서는 그 기간의 "가장 늦은 공시"가 10-K가 아니게 되어, `forms="10-K"`로 조회하면 그 기간이 통째로 빠진다. 지금의 순서에서는 `forms`가 "그 양식의 공시 안에서 기간마다 최신 값"을 뜻한다. `view=all`은 중복 제거 없이 거른 값 전부를 준다.

## 도구 구성

| 도구 | 내용 |
|---|---|
| `sec_find_company` | 티커·회사명·CIK로 회사 찾기 |
| `sec_filings` | 회사의 공시 목록 (양식·기간으로 거름) |
| `sec_financials` | 핵심 재무 항목의 연간·분기 시계열 |
| `sec_concept` | 임의의 XBRL 항목 하나의 시계열 |
| `sec_frames` | 한 기간에 한 항목을 공시한 모든 회사 비교 |
| `sec_search` | 공시 전문 검색 |
| `sec_document` | 공시 원문 텍스트 |

`sec_frames`는 회사마다 결산월이 다르다는 점을 감안해야 한다. SEC가 달력 기준에 가장 가까운 기간으로 맞춘 값을 주므로, 같은 "2023년"이라도 회사마다 실제 기간이 다를 수 있다.

## 출력 한도

도구 응답은 한 번에 6만 자까지이고 항상 유효한 JSON이다. 넘으면 `fitOutput()`이 행 수를 줄이고 `truncated: true`와 `note`를 붙인다. 공통 동작은 [MCP 서버 공통 구조](../architecture/server-anatomy.md)의 "출력 한도"에 있고, edgar에서의 세부는 다음과 같다.

- 최상위에 `rows`가 있으면 그것을 줄인다. `shown`이 있던 결과는 실제 행 수로 고치고, `sec_search`의 `next_offset`도 줄인 뒤 기준으로 다시 맞춘다.
- 최상위 `rows`가 없으면 안쪽의 배열을 모두 같은 수로 줄인다. `sec_financials`가 이 경우다. 항목마다 `rows`가 따로 있으므로 항목마다 같은 수만큼 최신 기간을 남긴다.
- 남기는 쪽은 앞쪽이다. 건수 제한 인자(`limit`, `top`, `size`)가 남기는 최신·상위 쪽과 같다.
- 안내 문구는 도구 이름별 표 `TRUNC_HINT`에서 고른다. `truncated`와 `note`는 행 배열보다 앞에 놓아 먼저 보이게 한다.
- 원문 텍스트처럼 줄일 행이 없는 결과가 넘으면 앞부분만 `preview`에 담는다.

## 공시 원문 읽기

`sec_document`는 원문을 받아 태그를 지운 텍스트로 돌려준다. [DART 서버](dart.md)의 원문 도구와 같은 방식으로 `offset`·`max_chars`로 나눠 읽거나 `find`로 단어 주변만 볼 수 있다.

EDGAR 원문에 고유한 처리가 두 가지 있다.

- 인라인 XBRL 문서의 `ix:header` 블록을 먼저 지운다. 사람이 읽는 본문이 아닌 메타데이터가 길게 들어 있기 때문이다.
- PDF는 텍스트로 바꾸지 못한다. 앞 4바이트로 PDF를 감지해 주소로 직접 열라는 오류를 낸다.

변환한 텍스트는 최근 3건을 메모리에 두어, 긴 문서를 나눠 읽을 때 매번 다시 받지 않는다.

## 반영 시각

SEC 공식 문서 기준으로 공시 이력은 보통 1초 이내, XBRL 자료는 1분 이내에 반영된다. 기록은 [데이터 반영 시각과 거래소 기준](../concepts/data-timing.md)에 있다.
