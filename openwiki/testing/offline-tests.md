# 오프라인 테스트

서버마다 네트워크와 인증 정보 없이 실행되는 테스트가 하나씩 있다. 테스트 프레임워크를 쓰지 않고 Node.js 내장 `assert`만 쓴다. 파일을 그대로 실행하면 되고, 실패하면 프로세스가 0이 아닌 코드로 끝난다.

```bash
node krx/test/offline.test.js
node dart/test/offline.test.js
node ecos/test/offline.test.js
node toss/test/test.js
node kis/test/offline.test.js
node fred/test/offline.test.js
node edgar/test/offline.test.js
```

toss만 파일 이름이 `test.js`다.

## 이 테스트가 맡은 역할

테스트는 두 가지를 보장한다.

**배포 관문.** 각 서버의 `pack.sh`가 확장 파일을 묶기 전에 이 테스트를 실행한다. 실패하면 확장 파일이 만들어지지 않는다([설치와 확장 패키징](../operations/install-and-packaging.md)).

**조회 전용 원칙의 회귀 방지.** 주문 경로나 다른 호스트로의 호출이 코드에 들어오면 테스트가 실패한다. 실계좌에 연결된 키를 쓰는 toss와 kis에서 특히 중요하다.

테스트가 **보장하지 않는 것**도 분명하다. 가짜 응답은 작성자가 예상한 형태일 뿐이다. 제공처가 실제로 어떤 값을, 어떤 단위로, 어떤 오류 형식으로 주는지는 실제 호출로만 알 수 있다. kis를 만들 때 실제 조회에서 처음 드러난 사실(없는 종목에도 정상 응답이 오는 것, 한도 초과가 HTTP 500으로 오는 것, 응답이 300일치로 오는 것)은 그 뒤에 테스트에 추가됐다. 실제 호출로 확인한 내용은 [데이터 반영 시각과 거래소 기준](../concepts/data-timing.md)과 `DATA_TIMING.md`에 기록한다.

## 외부 호출을 대체하는 세 가지 기법

서버가 HTTP를 보내는 방식에 따라 대체 기법이 다르다.

### 1. 전역 fetch 교체 (toss, kis)

toss와 kis는 내장 `fetch`를 쓴다. 테스트가 `global.fetch`를 가짜 함수로 바꾼 뒤 서버 모듈을 불러온다. 가짜 함수는 주소와 메서드, 헤더를 기록하고 경로에 따라 준비한 응답을 돌려준다.

가짜 함수 자체가 검문소 역할을 한다. 모든 호출에서 주소의 출처가 고정 호스트인지, 토큰 발급이 아닌 호출이 GET인지 단언한다. 어떤 테스트 경로에서든 다른 곳으로 요청이 나가면 즉시 실패한다.

### 2. 로컬 가짜 서버 (krx, ecos, fred)

이 서버들은 `https` 모듈을 직접 쓴다. 테스트가 `127.0.0.1`의 임의 포트에 HTTP 서버를 띄우고, 서버 모듈의 `_setHost()`로 호출 대상을 그 포트로 바꾼다. 실제 소켓을 거치므로 주소 조립, 헤더, 응답 해석이 운영과 같은 코드 경로로 검증된다.

`_setHost()`는 테스트용 환경변수가 켜져 있을 때만 동작한다. 운영 중인 서버의 호출 대상을 바꾸는 통로가 되지 않는다.

### 3. 내부 함수 주입 (edgar, dart)

edgar는 `_setFetcher()`로 주소를 받아 응답 본문을 돌려주는 함수를 끼워 넣는다. dart는 `_setCorpList()`로 회사 목록을 직접 넣어, 큰 목록 파일을 받는 단계를 건너뛴다.

## 테스트 전용 스위치

서버 모듈은 불리면 바로 표준 입력을 읽기 시작한다([MCP 서버 공통 구조](../architecture/server-anatomy.md)). 테스트는 모듈을 불러오기 **전에** 환경변수를 설정해 이를 끈다.

| 서버 | 환경변수 |
|---|---|
| toss, kis | `TOSS_MCP_NO_MAIN=1`, `KIS_MCP_NO_MAIN=1` |
| krx, dart, ecos, fred, edgar | `<이름>_MCP_NO_STDIO=1` |

실제 사용자 파일을 건드리지 않게 하는 장치도 있다.

- toss, kis, edgar의 테스트는 `HOME`을 임시 디렉터리로 바꾼다. 토큰과 캐시가 임시 위치에 만들어지고, 사용자의 실제 토큰 캐시는 그대로다.
- ecos는 `ECOS_MCP_CACHE_DIR`로 캐시 위치를 바꾼다. 이 변수도 테스트 스위치가 켜져 있을 때만 효력이 있다.

서버는 내부 함수를 `module.exports`로 내보낸다. 테스트는 MCP 메시지를 거치지 않고 `handle()`을 직접 부르거나, 값 변환·날짜 계산 같은 순수 함수를 따로 시험한다. 이름이 `_`로 시작하는 내보내기는 테스트 전용이다.

## 무엇을 검사하나

kis의 테스트를 예로 들면 다음을 확인한다. 다른 서버도 해당하는 부분을 같은 방식으로 본다.

**요청이 맞게 나가는가.** 도구마다 기대하는 경로, 거래 ID, 쿼리 인자를 표로 두고 실제 나간 요청과 대조한다. 표에 없는 도구가 있으면 "시험하지 않은 도구가 있음"으로 실패하므로, 도구를 추가하면 테스트도 추가해야 한다.

**토큰 수명주기.**
- 두 번째 호출에서 토큰을 다시 발급하지 않는다.
- 캐시 파일의 권한이 600이고, 파일에 키가 들어 있지 않다.
- 만료 시각을 한국 시각으로 해석한다.
- 방금 발급한 토큰이 거부되면 재발급하지 않고 안내한다.
- 오래된 토큰이 만료되면 한 번만 재발급한다.
- 동시에 5건을 불러도 발급은 한 번이다.

**오류 처리.** 한도 초과는 한 번 재시도하고, 계속되면 오류로 돌려준다. HTTP 200이어도 본문 코드가 실패면 오류다. 없는 종목의 0 채움 응답은 오류로 바뀐다.

**비밀 값 가리기.** 가짜 서버가 오류 본문에 키와 토큰을 되돌려 보내게 하고, 최종 오류 문구에 그 문자열이 없는지 확인한다.

**입력 검증.** 잘못된 인자 여러 건을 넣고, 모두 오류로 끝나며 **외부로 나간 요청 수가 늘지 않았는지** 확인한다. 검증이 요청 전에 이루어진다는 것을 보장한다.

**실제 표준 입출력.** 서버 파일을 자식 프로세스로 띄워 `initialize`, 알림, 깨진 줄, 도구 호출을 보내고 응답을 확인한다. 인증 정보 자리에 치환되지 않은 자리표시자를 넣어, 그것을 키로 착각하지 않고 설정 안내를 돌려주는지 본다. 응답 순서는 보장되지 않으므로 `id`로 찾는다.

## 조회 전용 원칙을 지키는 단언

toss와 kis의 테스트는 동작만이 아니라 **소스 코드 자체**를 검사한다.

kis의 경우 세 가지다.

1. 테스트 전체에서 나간 요청 중 GET이 아닌 것은 토큰 발급 경로로 가는 POST뿐이어야 한다.
2. 서버 소스 파일에 주문 경로 조각, 계좌 항목 이름, 주문용 해시 경로, 모의투자 도메인 문자열이 없어야 한다.
3. `READ_ENDPOINTS`의 모든 경로가 시세 조회 경로 형식이어야 하고, 거래 ID가 주문·계좌용 접두어로 시작하지 않아야 한다.

2번은 주석에도 적용된다. 서버 파일에 주문 경로를 주석으로 적어도 테스트가 실패한다. 의도된 엄격함이다.

toss의 테스트도 주문·계좌 경로가 코드에 없는지 확인하고, 마지막에 실제로 나간 호출 목록을 출력한다.

## krx의 명세 대조

krx는 도구가 명세 표에서 만들어지므로 테스트가 표 자체를 검사한다. API가 공식 31개인지, 경로와 (도구, type) 조합에 중복이 없는지, 분야별 개수가 맞는지, 출력 항목 수가 공식 화면에서 수집한 값과 같은지 확인한다. 표를 잘못 고치면 여기서 걸린다.

krx는 Claude Desktop의 실행 방식도 흉내 낸다. 서버 파일을 다른 스크립트에서 불러온 상태로 띄워, `require.main` 판정 없이도 서버가 시작되는지 확인한다.

## 테스트를 추가할 때

- 실제 호출에서 예상과 다른 응답 형태를 발견하면, 그 형태를 가짜 응답으로 추가하고 기대 동작을 단언한다.
- 새 도구는 요청 대조 표와 잘못된 입력 목록에 함께 넣는다.
- 가짜 응답의 값은 실제 응답에서 본 형식(숫자가 문자열인지, 쉼표가 있는지)을 따른다.
- 시간에 의존하는 동작(토큰 만료, 발급 제한)은 실제로 기다리지 않고 캐시 파일의 시각을 고쳐 재현한다.
